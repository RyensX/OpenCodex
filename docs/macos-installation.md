# Authorizing OpenCodex on First Launch on macOS

## Why does macOS prevent OpenCodex from opening?

The macOS installers for OpenCodex are not signed with an Apple Developer ID certificate and have not been notarized by Apple.

As a result, macOS may display the following message when you first open OpenCodex after downloading it from a browser:

> Apple cannot verify “OpenCodex.app” is free of malware that may harm your Mac or compromise your privacy.

This message is generated by the macOS Gatekeeper security system. It does not mean that macOS has detected malware in OpenCodex. It means that Apple cannot verify the developer identity or notarization status of the application.

Only download the installer from this project's [GitHub Releases](/releases) page.

## Recommended method: Allow the app in System Settings

### 1. Install the application

1. Download the DMG that matches your Mac:
   - Apple silicon (M1, M2, M3, M4, and later): `macos-arm64.dmg`
   - Intel Mac: `macos-x64.dmg`
2. Open the DMG.
3. Drag `OpenCodex.app` into the Applications folder.
4. Try to open OpenCodex from Applications.

### 2. Dismiss the security message

When macOS reports that it cannot verify the application, click **Done**.

Do not click **Move to Trash**.

### 3. Manually allow the application to run

1. Open the Apple menu .
2. Open **System Settings**.
3. Select **Privacy & Security**.
4. Scroll down to the **Security** section.
5. Find the message stating that `OpenCodex.app` was blocked.
6. Click **Open Anyway**.
7. Confirm with your login password or Touch ID when prompted.
8. Click **Open** in the confirmation dialog.

Afterward, macOS saves OpenCodex as a security exception. You should normally be able to open it directly in the future without repeating these steps.

> The **Open Anyway** button is normally available for approximately one hour after you attempt to open the application. If the button is not visible, try to open OpenCodex again and then return to Privacy & Security.

## Alternative method: Remove the quarantine attribute in Terminal

If **Open Anyway** does not appear in Privacy & Security, and you have confirmed that the installer came from this project's official GitHub Releases page, open Terminal and run:

```bash
xattr -dr com.apple.quarantine "/Applications/OpenCodex.app"
open "/Applications/OpenCodex.app"
```

The first command removes only the download quarantine attribute from OpenCodex. It does not disable Gatekeeper for the rest of the system.

## Verify the download

Before manually authorizing the application, confirm that:

- The installer came from `github.com/RyensX/OpenCodex`.
- The download link was on this project's GitHub Releases page.
- The filename and Mac architecture are correct.
- The SHA-256 digest matches the value displayed on the GitHub Release page.

To calculate the SHA-256 digest of the downloaded file:

1. Open Terminal.
2. Type `shasum -a 256 `, including the trailing space.
3. Drag the downloaded DMG file into the Terminal window.
4. Press Return to run the command.
5. Compare the result with the SHA-256 digest displayed next to the file on the GitHub Release page.
